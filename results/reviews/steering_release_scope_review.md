## 2. What each controller bundle contains (dynamic GCAD)

GCAD needs more than a direction. Each bundle needs these files:

- **`<trait>/bank.safetensors`:** the delta, key and demand tensors (Δ, K_pos
  and D̄) for each block, converted from `banks.pt`.
  - Record a hash map of the original pickle tensors and the converted
    tensors, and check that they are equal on load.
  - Never publish the `.pt` pickles: loading them can execute arbitrary
    code.
- **`<trait>/profile.json`:** taken from the retained profile, with local
  paths removed. It contains:
  - the base model ID and revision, the tokenizer hash and the rendering
    hash (the default template and system message);
  - the blocks, `base_coef`, the gate scale, `inverse: false`, and the gate
    and update formulas;
  - the attention implementation and dtype;
  - the generation settings the strength was calibrated on: greedy, cap 160
    for PF and SARC; temperature 1, cap 500 for impolite;
  - the measured held-out summary;
  - the pinned runtime versions (`torch 2.6.0`, `transformers 4.52.3`). The
    hook depends on Qwen2 attention internals.
- **`<trait>/provenance.json`:** hashes of the extraction inputs, the
  registrations and the closeout, plus the source licence of the text the
  bank was built from.
- **A small `runtime/` folder:**
  - the author's `gated_steerer` under Apache-2.0, with the author's NOTICE;
  - a thin loader that verifies the tensor hashes and the base revision and
    refuses a mismatched model or tokenizer;
  - one example script;
  - a self-test showing that coefficient 0 gives logits identical to the
    unhooked model.

## 4. Model card: claims and limits

**Allowed claims, one row per controller:**

- the model and revision;
- the task, the decoding and the evaluation design and size as each study
  actually used it. The designs differ:
  - PF and SARC: a 32-item held-out set of ordinary questions;
  - impolite: the author-reference task, with 60 first-reply responses on
    13 topics. This is not our 32-item held-out design.

  Do not imply that all three controllers share one held-out design;
- the metric as baseline → steered;
- the random-control result;
- the coherence cost;
- that the controller passed its predeclared development and held-out gates.

**Required limits:**

- **What it is:**
  - an inference-time hook, with no weight change;
  - individual controllers only. There is no joint, independence or
    disentanglement claim, and cross-trait coupling is reported descriptively
    (e.g. SARC–impoliteness r = .64).
- **Construct and measurement:**
  - the scales come from one Claude judge family;
  - coherence is not correctness or helpfulness;
  - small held-out sets;
  - truncation at the cap;
  - reconstructed artifacts and author-protocol differences.
- **SARC:** a narrow quality margin (coherence 70.72 against a floor of
  69.59).
- **Impolite:** shorter replies, and helpfulness not tested.
- **Calibration:** strengths are calibrated to each task and decoding setup
  and are not comparable across traits.
- **Small evaluation sets.** n is reported for each study as designed: 32
  held-out items for PF and SARC; 60 responses on 13 topics for impolite.
- **Refusal:**
  - use the protocol's frozen claim labels. A "coverage gain" is not a
    "hard-refusal reduction" when baseline FR was rare;
  - there is no harmful-prompt boundary claim, because there was no unsafe
    arm;
  - the Qwen3-4B raw-subtraction result stays a separate partial effect that
    failed its quality rule.
- **Intended use:** research. The PF and impolite controllers produce
  offensive text by design.

## 5. Reporting 4B nulls honestly

- **Show every result together.** Put the 7B and 4B outcomes for every
  trait and method in one table, with the same columns and each study's own
  pre-registered gates. Status values: `passed`, `development null`,
  `held-out failure`, `headroom closed` or `not run`, each with the gate that
  failed and its margin.
- **Say what transferred.** The 4B run is a quick control at fixed
  settings. It is **not** a new grid or tuning campaign.
  - The rule for mapping 7B blocks and settings onto 4B is **not yet
    registered**.
  - Report the exact mapping and procedure that is declared before any 4B
    output, then state for each trait what was carried over unchanged and
    what was freshly extracted (for example, banks).
  - Do not describe any block-fraction rule or grid as already transferred.
- **State the rule:** "Outcomes are model-specific. Differences between
  checkpoints do not establish an effect of model size, and a 4B null does not
  show that the method fails on small models."
- **Nothing is dropped.** Nulls stay in the release. 4B banks are published
  only where the 4B study passed, and are labelled with their own results.

## 6. Notes on `scripts/publish_release.py`

The tool is sound for its purpose. It uses an explicit file manifest,
re-hashes everything before upload, sets `exist_ok=False`, resumes only on an
exact match, verifies the remote hashes against a pinned revision, and never
records credentials.

**Before using it for the steering bank, add a preflight that refuses to
publish unless:**

1. the manifest contains `README.md`, `LICENSE` and `NOTICE`;
2. it contains **no unsafe pickle payloads** (`.pt`, `.pth`, `.pkl`, or a
   pickled `.bin`). Tensors are shipped as `.safetensors`. Reviewed runtime
   `.py` files, prose and licence files and JSON are allowed;
3. no file contains local absolute paths, run-log fragments, judge reasons or
   key-like strings, checked with a simple scan;
4. `private` is set explicitly.

**Load test.** The user has already authorized the release, so no further
approval is needed. A local package reload and the zero-coefficient parity
self-test against the pinned Qwen revision, run before publication, can serve
as the final concrete check. Publishing privately first and validating the
remote copy before making it public is recommended but optional.

**For GitHub:**

- check that `.gitignore` covers `outputs/` and `.hf/`;
- run a secret scan;
- tag the release commit, and record that commit in the Hugging Face card.
